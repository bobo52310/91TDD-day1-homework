# TDD 基本概念與流程

## 什麼是 TDD？

TDD（Test-Driven Development，測試驅動開發）是一種軟體開發方法論，其核心概念是：**先寫測試，再寫程式碼**。

## TDD 的三大法則

1. **在寫好失敗的單元測試之前，不要撰寫任何產品程式**
2. **只撰寫剛好能夠導致失敗的單元測試（編譯失敗也算失敗）**
3. **只撰寫剛好能通過當前失敗測試的產品程式**

## TDD 開發循環：Red-Green-Refactor

TDD 的開發流程遵循一個簡單的循環：

```
Red（紅燈）→ Green（綠燈）→ Refactor（重構）→ Red...
```

### 1. Red（紅燈階段）

- **撰寫一個會失敗的測試**
- 此時測試應該無法通過，因為功能還未實作
- 確保測試真的會失敗，避免「假陽性」

**範例：**
```php
// 先寫測試，此時程式碼還不存在
public function testCalculateSum()
{
    $calculator = new Calculator();
    $result = $calculator->sum(2, 3);
    $this->assertEquals(5, $result);
}
```

### 2. Green（綠燈階段）

- **撰寫最少量的程式碼讓測試通過**
- 不需要考慮最佳化或完美設計
- 目標只有一個：讓測試變綠燈

**範例：**
```php
class Calculator
{
    public function sum($a, $b)
    {
        return $a + $b;  // 最簡單的實作
    }
}
```

### 3. Refactor（重構階段）

- **在測試通過的前提下，改善程式碼品質**
- 消除重複程式碼
- 改善命名、結構、設計模式
- 確保重構後測試仍然通過

**範例：**
```php
class Calculator
{
    public function sum($a, $b)
    {
        // 加入型別檢查，提升程式碼品質
        if (!is_numeric($a) || !is_numeric($b)) {
            throw new InvalidArgumentException('參數必須是數字');
        }
        return $a + $b;
    }
}
```

## TDD 的優點

1. **高測試覆蓋率**：每一行程式碼都是為了通過測試而寫
2. **更好的設計**：先思考介面和使用方式，再實作細節
3. **快速回饋**：立即知道程式碼是否正確
4. **重構信心**：有測試保護，可以放心重構
5. **活文件**：測試本身就是程式碼的使用說明

## TDD 的挑戰

1. **學習曲線**：需要時間適應先寫測試的思維
2. **初期較慢**：一開始可能會覺得開發速度變慢
3. **需要紀律**：必須嚴格遵守 TDD 流程
4. **測試維護**：測試程式碼也需要維護

## TDD vs 傳統開發流程

| 項目 | 傳統開發 | TDD |
|------|----------|-----|
| 開發順序 | 程式碼 → 測試 | 測試 → 程式碼 |
| 測試時機 | 開發後補測試 | 開發前先寫測試 |
| 測試覆蓋率 | 通常較低 | 通常較高 |
| 重構信心 | 較低 | 較高 |
| 設計品質 | 容易過度設計或設計不足 | 剛好夠用的設計 |

## 實務建議

1. **從小處開始**：選擇簡單的功能練習 TDD
2. **保持測試簡單**：一個測試只測一件事
3. **快速迭代**：Red-Green-Refactor 循環要快
4. **不要跳步**：嚴格遵守 TDD 三法則
5. **持續練習**：TDD 是一種技能，需要刻意練習
